# Data Dictionary & Synthetic Dataset Provenance (`docs/data_dictionary.md`)

## 1. Dataset Provenance & Synthetic Labeling

- **Source:** Deterministically generated by `scripts/generate_demo_data.py` (`seed = 202604`).
- **Time Horizon:** `365` consecutive days (`2025-10-15` to `2026-10-14`) × `3` daily meals (`breakfast`, `lunch`, `dinner`) = `1,095` meal-service records.
- **Explicit Synthetic Flag:** Every synthetic row carries `is_synthetic = 1` in `meal_service_records`, `recipients`, and `surplus_listings`.
- **Assumptions Encoded in Generator:**
  - Base weekday attendance: `310` (breakfast), `540` (lunch), `470` (dinner).
  - Day-of-week multipliers: Monday–Thursday (`1.02–1.05`), Friday (`0.95`), Saturday (`0.78`), Sunday (`0.74`).
  - Menu category multipliers: `festive_thali` (`+22%` to `+24%`), `continental_fusion` (`+15%` dinner), `south_indian_special` (`+12%` breakfast), `healthy_millet_bowl` (`-9%` to `-11%`).
  - Holiday and semester-break reductions: Scheduled campus holidays (`-42%`), June/late-December semester breaks (`-32%`).
  - Campus events: `exam_week` (`+11%`), `campus_hackathon_fest` (`+20%`), `sports_meet` (`+8%`).
  - Historical planning inefficiency: Simulated cafeteria operators historically over-prepared on holidays (`+24%` over true demand) and weekends (`+15%`), generating realistic baseline leftovers.

## 2. Relational Database Tables (12 Core Entities)

### 2.1 `meal_service_records`
| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` | `PRIMARY KEY AUTOINCREMENT` | Unique record identifier |
| `service_date` | `TEXT` | `NOT NULL`, `UNIQUE(service_date, meal_type)` | Service date (`YYYY-MM-DD`) |
| `meal_type` | `TEXT` | `CHECK IN ('breakfast','lunch','dinner')` | Meal slot |
| `menu_category` | `TEXT` | `NOT NULL` | Menu category identifier |
| `menu_items` | `TEXT` | `NOT NULL` | Comma-separated dish description |
| `day_of_week` | `INTEGER` | `CHECK BETWEEN 0 AND 6` | `0 = Monday` ... `6 = Sunday` |
| `is_holiday` | `INTEGER` | `DEFAULT 0` | `1` if scheduled holiday, else `0` |
| `special_event` | `TEXT` | `DEFAULT 'none'` | `none`, `exam_week`, `sports_meet`, `campus_hackathon_fest` |
| `weather_condition` | `TEXT` | `DEFAULT 'clear'` | `clear`, `rainy`, `extreme_heat`, `cold_fog` |
| `temperature_c` | `REAL` | `DEFAULT 28.0` | Ambient temperature (°C) |
| `meals_prepared` | `INTEGER` | `CHECK >= 0` | Total portions prepared by kitchen |
| `meals_served` | `INTEGER` | `CHECK >= 0`, `<= meals_prepared` | Portions actually served to diners |
| `leftover_portions` | `INTEGER` | `CHECK >= 0` | Unserved portions (`meals_prepared - meals_served`) |
| `food_discarded_portions` | `INTEGER` | `CHECK >= 0`, `<= leftover_portions` | Leftover portions ultimately discarded as waste |
| `unmet_demand_portions` | `INTEGER` | `CHECK >= 0` | Estimated unserved demand when food ran out |
| `is_synthetic` | `INTEGER` | `DEFAULT 1` | `1` for synthetic demo data, `0` for genuine records |

### 2.2 `demand_forecasts` & `model_evaluation_runs`
- **`demand_forecasts`**: Stores `forecast_date`, `meal_type`, `menu_category`, `predicted_demand`, `rounded_operational_demand`, `baseline_demand`, `planning_buffer_portions`, `upper_bound_demand`, `lower_bound_demand`, `model_version`, `is_fallback_baseline`, and `contributing_factors_json`.
- **`model_evaluation_runs`**: Stores chronological split ranges (`train_start_date`, `train_end_date`, `eval_start_date`, `eval_end_date`), `ml_mae`, `ml_rmse`, `ml_wape`, `ml_bias`, `baseline_mae`, `baseline_rmse`, `baseline_wape`, `baseline_bias`, `selected_model`, `residual_std`, `residual_q85`, `feature_importances_json`, and `artifact_path`.

### 2.3 `production_plans`
- Stores `service_date`, `meal_type`, `forecast_id`, `predicted_demand`, `planned_production`, `recommended_production`, `production_capacity`, `shortage_risk_tolerance`, `safety_buffer_portions`, `expected_surplus_existing_plan`, `expected_surplus_recommended_plan`, `expected_shortage_risk_existing`, `expected_shortage_risk_recommended`, post-service `actual_production`, `actual_served`, `actual_leftover`, `actual_discarded`, and `explanation`.

### 2.4 `surplus_listings`, `recipients`, `redistribution_offers`, `redistribution_transactions`
- **`surplus_listings`**: Tracks `listing_code`, `food_description`, `food_category`, `initial_quantity_portions`, `remaining_quantity_portions`, `reserved_quantity_portions`, `collected_quantity_portions`, `preparation_time`, `available_from_time`, `pickup_deadline`, `safe_use_deadline`, `storage_condition`, `safety_approved`, and `status` (`DRAFT`, `AVAILABLE`, `PARTIALLY_RESERVED`, `RESERVED`, `COLLECTED`, `CANCELLED`, `EXPIRED`).
- **`recipients`**: Stores organization profile, `latitude`, `longitude`, `accepted_categories_json`, `max_capacity_portions`, `pickup_window_start`, `pickup_window_end`, `is_verified`, `is_active`, and `priority_tier`.
- **`redistribution_offers`**: Tracks `offer_code`, `listing_id`, `recipient_id`, `offered_quantity_portions`, `accepted_quantity_portions`, `collected_quantity_portions`, `uncollected_quantity_portions`, `match_score`, `match_reasons_json`, and `status` (`PENDING`, `ACCEPTED`, `DECLINED`, `COLLECTED`, `CANCELLED`, `EXPIRED`).
- **`redistribution_transactions`**: Immutable ledger recording every `OFFER_CREATED`, `OFFER_ACCEPTED`, `OFFER_DECLINED`, `OFFER_CANCELLED`, and `COLLECTION_CONFIRMED` event.

### 2.5 `users`, `roles`, `audit_events`, `application_settings`
- Enforces role-based access control, stores PBKDF2-HMAC-SHA256 password hashes, logs consequential actions in `audit_events`, and persists configurable cafeteria parameters in `application_settings`.
